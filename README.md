# tmux web

ローカルの tmux を、ブラウザから GUI で操作するためのアプリ。
セッション・ウィンドウの一覧と操作をボタンで行い、端末そのものは xterm.js で表示する。
開いた端末はブラウザと同じ**タブ**になり、並べて見たいときだけ画面を割る。
`C-b` から始まるキー操作を覚えていなくても tmux が使える。

```
┌──────────────────┬──────────────────────┬──────────────────────┐
│ プロジェクト一覧 │ ●tmux-web │●NHK ＋   │ ● Devcamp       ＋   │  ← タブ列
│                  ├──────────────────────┼──────────────────────┤
│ ▾ tmux-web  ●1 ○2│                      │                      │
│  ● 一覧を直す    │                      │                      │
│    作業中 Claude │      ターミナル      │      ターミナル      │
│  ○ ビルド確認    │                      │                      │
│    未使用・2時間 │                      │                      │
├──────────────────┴──────────────────────┴──────────────────────┤
│ Esc Tab ^C ^D ^Z ^L ^R ← ↓ ↑ → Home End PgUp PgDn              │
└────────────────────────────────────────────────────────────────┘
```

## 使い方

Linux では Node.js 20 以上、npm、tmux、git が必要。自動起動には
`systemd --user` と `loginctl` が使えるユーザーセッションが必要。
Ubuntu 24.04 で tmux / git がなければ `sudo apt install tmux git` で導入する。

この PC に常用環境をまとめて導入するには:

```bash
./scripts/setup.sh      # 依存関係・ビルド・Web/tmux 自動起動・保存/復元を導入
                       # ブラウザで http://127.0.0.1:7654
```

起動用の tmux セッション `0` を作り、保存があれば構成を復元する。
既に動作中の tmux セッションはそのまま使う。設定はユーザー単位で導入する。
再起動前には `./scripts/resurrect-autosave.sh` で最新の構成を保存できる。

`setup.sh` は bash / zsh の対話シェルにも tmux の自動起動を設定する。
Terminator、GNOME Terminal、VS Code などで開く新しい端末・タブ・分割が、それぞれ
独立した tmux セッションになり、tmux-web の一覧に表示される。開始フォルダーは引き継ぐ。
既存のシェル設定は残し、変更前のバックアップを起動ファイルの隣に作成する。
tmux 内や非対話のスクリプト、`bash -ic 'command'` などの明示的なコマンドでは起動しない。

端末の設定だけ導入・更新する場合は `./scripts/install-terminal-tmux.sh` を実行する。
このスクリプトはマウス操作とホイールでの履歴スクロールも設定し、動作中の tmux に即時反映する。
既存の tmux 設定はバックアップして残し、`~/.config/tmux-web/terminal.conf` の読み込みを追記する
（`XDG_CONFIG_HOME` を指定している場合はその配下）。履歴は新しいペインから最大 50,000 行保持する。
マウス対応アプリにはホイールを渡す。マウス非対応の全画面CLI（Codexなど）では
PageUp / PageDown を送り、CLI自身の会話・画面をスクロールする。通常シェルでは tmux の履歴を表示する。
全画面CLIの会話履歴は tmux の履歴に残らないことがあるため、tmux の履歴表示へ強制的に切り替えない。
明示的に tmux の履歴表示へ入った場合は、そちらのスクロールを優先する。履歴表示は `q` で戻る。
分割画面ではマウスポインター下のペインを対象にする。

別 PC で導入済みなのにホイールが上矢印キーのように動く場合は、その PC のリポジトリで更新する:

```bash
git pull --ff-only
./scripts/install-terminal-tmux.sh
```

開いたままの通常の bash 端末は `source ~/.bashrc` で tmux に入れる
（実行中のコマンドは先に終了する）。一時的に素のシェルを使うには
`TMUX_WEB_AUTO_START=0 bash`、自動起動を無効にするには起動ファイルの
`# tmux-web: terminal auto-start` から始まるブロックを削除する。

一時的に手動で起動するなら:

```bash
npm ci
npm run serve          # ビルドして起動 → http://127.0.0.1:7654
```

開発するときは:

```bash
npm run dev            # Vite (5173) + API サーバ (7654) を同時起動
                       # ブラウザで http://localhost:5173
```

## できること

### スマホでのタブ操作・エージェント起動

タブが増えても表示幅を保ち、タブ列を指で横スクロールできる。
列の右のタブ一覧から直接選べる。指でスクロールしている途中では選択・並べ替えを行わない。
PC で分割していた配置はスマホでは選択中の端末を全面表示する。
別の端末はセッション一覧、または「その他の操作 → ウィンドウを切り替える」から選べる。
PC の幅に戻すと保存した分割表示に戻る。

上部の **Claude / Codex** ボタンは現在の作業フォルダーで新しいタブに CLI を起動する。
サーバ側に各 CLI がインストールされている必要がある。終了時はシェルに戻る。
フォルダーアイコンからファイル一覧・プレビューを開ける。

### プロジェクトを作る・会話を再開する

サイドバーの **「＋ プロジェクトを作る」** から名前を入力すると、フォルダーと Git リポジトリを作り、
そのまま通常の端末タブで開く。Node.js / Python のテンプレートと、Claude / Codex / ターミナルを選べる。
保存先はホームが既定で、「保存先を変更」から指定できる。最初の指示も一緒に渡せる。
既存のフォルダーは **「フォルダーを開く」** から開く。同名のフォルダーは上書きしない。
CLI が信頼の確認を求めた場合は、開いた端末で確認する。

**「最近のClaude履歴」** は同じサイドバーにある。プロジェクト名やパスで検索し、クリックすると
直近の会話を新しいタブで再開する。履歴は `~/.claude/projects` を参照し、移動・削除済みのフォルダーは省く。
開いているタブと分割配置は維持する。tmux 自体のセッションを追加する場合は「セッション別」で作成できる。

Claude が動いている端末では、「その他の操作 → Claude アプリに接続」から Remote Control を有効にできる。
新規作成時に「Claude アプリからも操作する」を選ぶこともできる。
Claude アプリへの接続準備や終了操作は、その端末のメニューにまとまっている。

### スマホからの sudo 承認

```bash
./scripts/sudo-web.sh <command> [args...]
```

実行待ちになると、端末の上に **「sudo 承認待ち」** が表示される。
「内容を確認」からコマンド・作業フォルダー・スクリプトの内容を読み、承認または拒否する。
パスワードはエージェントへ渡さず、sudo ヘルパーが一度だけ受け取る。150秒で期限切れになる。
外部からの入力は HTTPS が必要。別ポートの場合は `TMUX_WEB_URL=http://127.0.0.1:<port>` を指定する。

これらは既存の React 画面と Express API に組み込まれており、別の管理アプリ・iframe・専用認証は使わない。
`claude-launcher.service` と7777番ポートは廃止済み。既存の会話履歴と tmux セッションをそのまま使う。

### 複数の端末を見分ける

ホスト名の SHA-256 ハッシュから色と模様を生成し、ファビコン、ホーム画面アイコン、
テーマカラー、下部バーに反映する。ブラウザのタイトルと下部バーには端末名も表示する。
同じ端末名なら再起動しても同じ色・アイコンになる。
表示名を変える場合はサービスの環境変数 `TMUX_WEB_DEVICE_NAME` を設定する。

### 仮想デスクトップ（画面全体の切り替え）

画面上部のバーで、タブと分割配置をまとめて切り替えられる。
例えば「フロント開発」と「GPU学習」の画面を分け、それぞれにPC・Sparkの端末を配置できる。

- 上部の **＋** で空のデスクトップを追加する。
- 名前をクリックして切り替える。ダブルクリック、または **✎** で名前を変更する。
- `Alt+Shift+← / →` で前・次のデスクトップへ、`Alt+Shift+N` で新しく追加する。
- 各画面のタブ・分割配置・選択中のタブ・フォーカスした分割・デバイスをブラウザに保存する。
  再読み込み後も、最後に使ったデスクトップから再開できる。
- 切り替えた画面の端末も接続を維持し、実行中の処理を継続する。
  キー入力とショートカットは表示中のデスクトップだけが受け取る。
- 名前の右の **×** で、そのデスクトップの配置を削除できる。
  tmuxと実行中の処理は残るので、別のデスクトップの一覧から再び開ける。
  最後の1つは削除できない。

従来のタブ・分割配置は「デスクトップ1」にそのまま引き継ぐ。
デスクトップの構成はブラウザ単位の保存で、別のブラウザ・端末とは同期しない。

### 複数デバイスを同じ画面で使う

サイドバー上部のデバイス選択の右にある **＋（デバイス接続）** から、
DGX Spark など、別マシンで起動している tmux-web を登録できる。
接続先URLは `http://ホスト名:7654` または Tailscale Serve の HTTPS URL を入力し、
接続先に `TMUX_WEB_TOKEN` がある場合はトークン欄へ入力する。
登録済みデバイスの **編集** から接続先・トークンを更新できる。トークン欄が空なら既存の値を維持する。
URLにはパスや `?token=...` を含めない。接続先を新しいコードへ更新する必要はない。

- サイドバーはデバイスごとにプロジェクト・セッションを表示する。
- 一覧から別デバイスのウィンドウを開いたり、端末の端へドラッグして並べられる。
- 各タブ列の「デバイス ＋」から、選んだデバイスに新しい端末タブを作成できる。
- タブにデバイス名を表示する。Claude / Codex の起動・ファイル閲覧・アップロードも
  その端末があるデバイスで行う。デスクトップ表示はサイドバー上部で選択したデバイスへ接続する。
- プロジェクト作成・最近のClaude履歴・tmuxセッション作成は上部で選択したデバイスが対象。
- 切断されたデバイスのタブ・配置は保持し、自動で再接続する。
  tmux の再起動後は同じデバイス内の名前・番号を使って配置を復元する。
- デバイス間で実行中のプロセス・ファイルを移動する機能は含まない。
  セッションの結合や tmux ウィンドウの移動は同じデバイス内だけで行う。
  sudo承認は画面配信元のPCが対象。

ブラウザから各デバイスへ直接接続せず、この画面を配信しているPCがHTTP・WebSocketを中継する。
配信元PCから接続先へ到達できる必要がある。入口のPCが停止すると統合画面も利用できなくなるが、
各マシン上のtmuxとプロセスは継続する。接続先には信頼できるマシンのURLを登録する。

設定と接続先トークンは配信元PCの `~/.config/tmux-web/devices.json` に権限0600で保存し、
ブラウザのデバイス一覧にはトークンを返さない。保存先は `TMUX_WEB_DEVICES_FILE` で変更できる。
登録・削除と中継には既存の `TMUX_WEB_TOKEN` 認証を使用する。

### リモートデスクトップ

上部のモニターアイコンから、この PC のデスクトップを表示・操作できる。
ブラウザ用 VNC クライアント [noVNC 1.7.0](https://github.com/novnc/noVNC/tree/v1.7.0)
と、既にログインしている X11 画面を共有する [x11vnc](https://github.com/LibVNC/x11vnc) を使用。

- **画質・遅延設定**で「低遅延」「バランス」「文字くっきり」を選べる。初期値はバランス。
  JPEG品質（0〜9）、圧縮レベル（0〜9）、配信サイズ（100/75/50%）、更新間隔（16/33/66/100ms）を個別調整し、
  「適用して再接続」で反映する。設定はブラウザに保存する。スライダー操作中は再接続しない。
- JPEG方式は Tight 圧縮で通信量を抑える。「文字くっきり」は元の解像度・24bitカラー・可逆圧縮（ZRLE）。
  高圧縮は通信量を減らす代わりにCPU負荷が増える。更新間隔は画面走査の待ち時間で、FPSの上限・保証ではない。
- マウス・キーボード、右クリック、スクロール、Esc / Ctrl+Alt+Del の送信。
- 配信サイズはサーバーで縮小して通信量を削減する。この接続だけに適用し、PC自体の解像度は変えない。
  「原寸表示」は配信画像をそのまま表示。「画面に合わせる」はブラウザ側だけで縮小する。
- 全画面、閲覧専用、再接続。Esc はデスクトップ内ではリモートに送る。
- 「文字・クリップボード」で日本語を入力し、リモートの入力先を選んでから「リモートへ貼り付け」。
  Ctrl+V を送るため、端末アプリなどでは入力欄に用意した文字を送信後、アプリ側の貼り付け操作を使う。
  「リモートからコピー」でリモートのクリップボードを入力欄とこの端末へ取り込む。
- スマホはタップでクリック、2本指タップで右クリック、2本指ドラッグでスクロール。

Linux **X11 のログイン済みデスクトップ**が対象。Wayland・ログイン画面・音声は未対応。
動画より、ブラウザ・エディタ・設定画面などの操作を優先した方式で、画面全体が頻繁に変わると帯域を多く使う。
遅いときはまず「低遅延」を試す。画面下の「通信往復」はHTTPの応答時間で、取り込み・圧縮・描画の時間は含まない。
同じWi-FiでもTailscaleが中継を使う場合があるため、`tailscale status` / `tailscale ping <端末名>` で
`direct` / LANアドレスになっているかを確認する。
配信側は x11vnc の過負荷検出による最大1.5秒の待機を無効化し、入力を優先して更新の追加待ちを抑える。
オプションの意味は [x11vnc OPTIONS](https://github.com/LibVNC/x11vnc/blob/master/doc/OPTIONS.md)、
品質・圧縮の段階は [noVNC API](https://novnc.com/noVNC/docs/API.html) を参照。
必要なシステム依存関係は次で導入する:

```bash
sudo apt install x11vnc x11-xserver-utils xclip
```

サービスから画面に接続できない場合は、デスクトップの端末で:

```bash
systemctl --user import-environment DISPLAY XAUTHORITY
systemctl --user restart tmux-web
```

`install-service.sh` も設定時にこの環境変数を引き継ぐ。
さらに X11 ログイン時の自動実行を登録し、現在の `DISPLAY` / `XAUTHORITY` を
引き継いで起動済みの tmux-web を再起動する。これにより、PC 起動時に GUI より先に
サービスが立ち上がった場合や、再ログインで画面番号が変わった場合も接続できる。
再起動中はブラウザの接続が一時的に切れるが、tmux セッションは維持される。
別の X ディスプレイを選ぶには `TMUX_WEB_DISPLAY` を設定する。
ヘッドレス環境でも tmux の機能は引き続き使える。

接続は既存の `TMUX_WEB_TOKEN` 認証と `/ws/desktop` を使い、Tailscale Serve の既存 URL で利用できる。
VNC 用の TCP ポートは開かず、権限 0700 の一時ディレクトリ内の Unix ソケットで中継する。
閉じるとその接続の x11vnc とソケットを片付ける。ブラウザを非表示にした間も接続は維持する。
従来の閲覧専用 MJPEG API (`/api/screen/*`) は互換用に残してあり、そちらだけ `ffmpeg` が必要。

noVNC は MPL-2.0 等で配布される。著者情報とライセンス本文は
[web/public/licenses/noVNC](web/public/licenses/noVNC) に同梱し、ビルド後も `/licenses/noVNC/` に配信する。
可逆圧縮の交渉は `web/src/vendor/lossless-rfb.ts` に分離し、noVNC 自体は改変していない。

### プロジェクト単位で、いま何が動いているかが分かる

サイドバーの既定は **プロジェクト別**。作業ディレクトリから git リポジトリのルートを
探して、同じリポジトリのウィンドウをセッションをまたいで 1 つの見出しにまとめる。
「1 ディレクトリ = 1 エージェント」で回しているとき、tmux のセッション名ではなく
ディレクトリ名で探せる。上の切り替えで **セッション別**（tmux の構造そのまま）にも戻せる。

各行の状態は、端末タイトルではなく **ペインのプロセスツリー** から決める。タイトルは
中のプロセスが終わっても残るので、それだけを見ていると終わったエージェントまで
動いているように見えてしまう。`pane_pid` の子孫を実際に辿って次の 5 状態に分ける。

| 表示 | 判定 |
| --- | --- |
| ● 作業中 | エージェント（`claude` / `codex` / `aider` など）が生きていて、タイトルに点字スピナーが出ている |
| ● 入力待ち | エージェントは生きているが手が止まっている＝こちらの返事待ち |
| ● サーバ稼働 | 子孫のどれかが TCP を待ち受けている。ポート番号をチップに出す（`:5173`） |
| ● 実行中 | シェル以外の何かが動いている。コマンド名をチップに出す |
| ○ 未使用 | シェルしかいない。最後の出力からの経過時間を添えて、行を薄く沈める |

エージェント名（`Claude` など）とポート番号は行の右にチップで出る。見出しの横には
`●3 ○7` のように状態ごとの件数が並ぶので、畳んだままでも稼働状況が読める。
上部の入力欄で、作業内容・ウィンドウ名・パス・状態を横断して絞り込める。

### 未使用のウィンドウは畳んで、まとめて片付けられる

再起動のたびに resurrect が昔のウィンドウを素の bash で戻すので、放っておくと
シェルしかいない行が何十枚も溜まり、動いているエージェントが埋もれる。そこで一覧は
**動いているものだけを前に出す**。

- 各プロジェクトの中は エージェント → その他の稼働中 → 未使用 の順。未使用の行は
  末尾の「▸ 未使用 N 枚」に畳まれ、押すと広がる。いま見ている・タブで開いている行は畳まない
- ウィンドウが全部未使用のプロジェクトは、一覧の一番下の「動いていないプロジェクト」に
  まとめて沈める
- 絞り込み欄の下に `● 作業中 3  ● 入力待ち 6  ○ 未使用 90` と全体の件数が出る。
  押すとその状態だけに絞り込む

**片付ける** ボタン（全体は件数の右、プロジェクトごとは「未使用 N 枚」の行にホバー）で、
未使用のウィンドウをまとめて閉じられる。閉じるのは、全ペインがシェルだけ（子プロセスなし）と
確かめられたものだけで、タブで開いているものと直近 10 分に出力があったものは残す。
サーバ側（`killIdleWindows`）でも閉じる直前にプロセスを取り直し、確認のあとで何か
動き出したウィンドウは閉じない。

判定は `server/src/inspect.js`。`ps` と `ss` を 1 回ずつ叩いた結果を全ペインで使い回す。
`ss` が無い環境ではポートの検出だけが落ちる。

### 画面まわり

VS Code の Dark+ に寄せてある。左端がアクティビティバー（一覧の開閉・切り替えパレット・
チートシート）、その右がセッション一覧、下が青いステータスバー。エディタ上部は 30px の細い
1 本だけで、左にパンくず、右によく使うアイコン（タブを追加・右に分割・下に分割・切り替え）、
残りは「⋯」にしまってある。その下が、タイルごとのタブ列。

### タブで開く

端末は**タブ**で開く。一覧でウィンドウをクリックすると、いま見ているタイルにタブが
1 枚増えて前面に出る。ブラウザや VS Code と同じで、いくつ開いても場所を取らない。

| やること | 操作 |
| --- | --- |
| 切り替える | タブをクリック / `Alt+1`〜`Alt+9` / `Alt+[` `Alt+]` |
| 新しい端末 | タブ列の ＋（`Alt+T`）。いま見ているペインと同じディレクトリで開く |
| 閉じる | タブの ✕ / 中クリック / `Alt+W` |
| まとめて閉じる | タブを右クリック →「他のタブを閉じる」「右側のタブを閉じる」 |
| 並べ替え | タブを掴んで左右に動かす |
| 別のタイルへ移す | タブを掴んで、そのタイルのタブ列に落とす |
| 並べて見る | タブを掴んで、端末の端（上下左右 30%）に落とす |
| 探す | `Alt+P` の切り替えパレット |

タブを閉じても **tmux のウィンドウは消えない**。画面から下ろすだけで、中のプロセスは
動いたまま。tmux ごと終わらせたいときはタブの右クリックから「ウィンドウを閉じる」。

タブには、一覧と同じ状態の点（作業中 / 入力待ち / サーバ稼働 / 実行中 / 未使用）が付く。
畳んだ端末でエージェントが手を止めたことに、タブの色で気付ける。

タイルの中の端末は 1 つで、タブを切り替えると映すウィンドウを差し替える。同じセッション内
なら tmux 側で `select-window` するだけなので一瞬で切り替わる。別のセッションのタブに移る
ときだけ attach し直すので、一度画面が描き直される。

### 切り替えパレット（Alt+P）

タブが増えてくると、目当ての端末を一覧から目で追うことになる。`Alt+P` を押すと、
**直前に見ていた順**にウィンドウが並んだパレットが出る。打てば絞り込め（プロジェクト名・
作業内容・パス・状態のどれでも当たる）、`↑` `↓` で選んで `Enter` で開く。すでにタブに
あるものは増やさず前面に出すだけで、「表示中」と印が付く。

### 見出しの主役はプロジェクト名

タブ・パンくず・一覧は、**作業ディレクトリのリポジトリ名を一番大きく**出す。
セッション名やウィンドウ番号（`0:[tmux]`）は tmux 側の都合で決まる名前で、
`claude` が 5 つ並んだときに見分ける役には立たない。並びはこうなる。

```
タブ    ● Devcamp2026  2:claude · aichallenge-mpc
          └ プロジェクト  └ ウィンドウ · セッション

一覧    ● 自律的な検証と改善                    Claude
          入力待ち · aichallenge-mpc · 2:claude
          └ 端末タイトル（＝いま何をしているか）
```

プロジェクトのルートより下で作業しているときは、その相対パスが名前の後ろに続く
（`Devcamp2026 /kosen-letter`）。セッション名がプロジェクト名と同じときは繰り返さない。

ブラウザのタブ名も、いま見ているタブのプロジェクト名になる
（`Devcamp2026 — tmux web`）。複数のウィンドウで開いたとき、タブの並びだけで
どれがどれか分かる。

### 分割 = 新しいウィンドウを隣に開く

上部バーの分割アイコンは、**tmux のペインを増やさない**。
Terminator と同じで、新しいウィンドウを作ってブラウザ側のタイルを割る。
1 ウィンドウ 1 ペインのままなので、境界線のドラッグやタイルの入れ替えが素直に効く。
新しい端末は、いま見ているペインと同じディレクトリで開く。

tmux のペインとして分割したいときは、端末を右クリックして
「tmux のペインとして分割」から行う。分割したペインは端末の中にそのまま出るので、
移りたいペインをクリックすれば選べる（ミラーはマウスを有効にしてある）。
ペインの縮図（旧「ペイン配置図」）は、1 ウィンドウ 1 ペインで使うぶんには出番がなく、
端末の中で直接クリックすれば済むので廃止した。

### 分割して同時に監視する

サイドバーのウィンドウやタブを**ドラッグして落とす**と画面が分割される。
落とす場所で入り方が決まる。

- タブ列 … その位置にタブとして差し込む（差し込み先に縦線が出る）
- 端末の端（上下左右 30%）… その向きに並べて 2 分割
- 端末の中央 … そのタイルにタブとして足す

分割は入れ子にできるので、3 枚以上を好きな配置で並べられる。境界線をドラッグすれば
比率を変えられ、配置とタブはブラウザに保存されて次に開いたときも復元される。
タブ列右端の ⨯ でタイルごと閉じる。ツールバーやキーバーの操作は、
タブに色の線が入っている**フォーカス中のタイル**に対して働く。

### 同じウィンドウを 2 枚開かない

すでにどこかのタブになっているウィンドウは、**もう 1 枚開かない**。

- 一覧やパレットで選んだ … そのタブが前面に出るだけ
- ドラッグして落とした … 増やさずに、そのタブが落とした場所へ移る

同じ端末が 2 枚並んでも中身は同じで、どちらを操作しているのか分からなくなるだけ。
ミラーセッションもタイルの数だけ増える。一覧では、いまタブになっているウィンドウに
「表示中」のバッジが付く。

tmux を再起動したあとの繋ぎ直しや、古い配置の復元で同じものを映す 2 枚が残った場合も、
気付いた時点で 1 枚に畳む（前面に出ているタブを残す）。

タッチ操作でも同じように動く（HTML5 のドラッグ API ではなくポインタイベントを使っている）。

### ウィンドウが消えたらタブも閉じる

ペインが消えてウィンドウも無くなったら、そのタブは**閉じる**。別のウィンドウを繋ぎ変えて
表示することはしない。閉じたはずの場所に関係ない端末が出てくると紛らわしいため。
タイルの最後の 1 枚だった場合は、タイルごと畳まれる。

ペインとウィンドウを閉じる操作には確認を挟む。タブを閉じるだけなら確認は要らない
（tmux 側は何も終わらないので、開き直せば元通り）。

全部閉じるとタブが 0 枚になり、サイドバーやパレットから選び直すまで何も開かない。
ただしページを読み込み直したときだけは、何も開いていないと不便なので
最初のセッションを 1 枚開く。

### 右クリックはアプリ側のメニューを出す

端末の右クリックは **tmux に送らず**、ブラウザ側で自前のメニューを出す。

tmux の `display-menu` に任せると、マウス報告が届くかどうか・コピーモード中かどうかで
出たり出なかったりする。実際、コピーモードに入っているペインでは `MouseDown3Pane` の
バインドが効かず、右クリックが無反応になる。自前で出せばどの状況でも同じに使える
（VS Code の端末も自前のメニューを出している）。

メニューには分割・コピー・貼り付け・全画面・ペイン/ウィンドウを閉じる、を並べてある。
**ブラウザ本来のメニューが要るときは Shift を押しながら右クリック。**

### 日本語入力（IME）

変換の確定文字は、xterm ではなく `compositionend` の `data` から直接送っている
（`web/src/components/Terminal.tsx`）。

xterm 5.5 は確定時に補助 textarea の `value.substring(start, end)` を切り出して送る。
`start` は変換開始時に同期で決まるのに `end` は `compositionupdate` の `setTimeout(0)` で
遅れて更新されるため、変換で文字数が変わる（「おは」→「おはようございます」）と
`end` が古いまま残る。次の変換では `start > end` となり、JS の `substring` は
その場合に**引数を入れ替える**ので、打ったはずの文字ではなく
「ひとつ前に入力した文章の断片」が送られてしまう。

補助 textarea は確定・Enter・blur のときしか消されず確定文が溜まり続けるので、
これが誤爆の材料になる。変換の前後で必ず空にし、確定文字は IME が確定した
`data` から送ることで、どちらの経路も断つ。変換の途中経過（下線付きの表示）は
これまでどおり xterm が描く。

#### 「？」「、」が 2 つ 3 つ並ぶ

xterm には確定文字を送る経路が 3 つあり、どれが動くかがイベントの届く順で変わる。

| 経路 | 動く条件 |
| --- | --- |
| `CompositionHelper._finalizeComposition` | 変換確定（上の `substring` の件） |
| `CompositionHelper._handleAnyTextareaChanges` | IME 有効時のキー（keyCode 229）。`setTimeout(0)` 後に textarea の増分を送る |
| `Terminal._inputEvent` | `input` イベントの `data`。`keyup` が `input` より先に来たときだけ通る |

「？」「、」のように IME が変換を挟まず即確定する文字は、確定してから補助 textarea に
書き戻される。こちらが `compositionend` で送ったあとに書き戻しが起きるので、
2 番目（増分検出）や 3 番目（`input`）が同じ文字をもう一度送っていた。
`keyup` の順で通る経路が変わるため、**出るときと出ないときがある**のがこの症状の質。

そこで IME が絡む入力（keyCode 229 の keydown、または変換確定の直後）は
`input` を capture 段階で受け取って xterm に渡さず、こちらだけが送る。
確定直後に同じ文字が戻ってきたぶんは捨て、補助 textarea は変換中以外つねに空にする
（空にしておかないと、増分検出が「減った」と見て `DEL` を送ってしまう）。
IME を経由しない挿入（絵文字パレットなど）は今までどおり xterm に任せる。

#### IME のあと、最初の英字・記号が 2 つ並ぶ

環境によっては `compositionend` のあとに、確定文字を書き戻す `input` が来ない。
この場合、上記の「確定直後の同じ文字を捨てる」ための印が次のキーまで残り、通常入力を
IME の後処理と誤認する。通常文字は xterm が `keydown` ですでに送っているため、独自の
`input` 処理でも送ると最初の 1 文字だけ二重になる。非 IME の `keydown` が来た時点で
確定文字の印を失効させ、それ以降は通常どおり xterm だけに送信を任せる。

### 切れても勝手に繋ぎ直す

端末の WebSocket が切れたら、0.5 秒から最大 5 秒までのバックオフで張り直す。
圏外・スリープ復帰・サーバの再起動で切れても、再読込せずに続きから使える
（tmux 側のセッションは生きているため）。`online` とタブの表示復帰を拾ったときは
待ち時間を飛ばしてすぐ繋ぎに行く。

### サイドバーに落とすと tmux 自体が動く

同じドラッグでも、**落とす先がサイドバーの木なら表示ではなく tmux が動く**。
右のターミナル領域に落とせば画面分割、サイドバーに落とせば移動、という使い分け。

| 掴むもの | 落とす先 | 起きること |
| --- | --- | --- |
| ウィンドウ | 別のセッション行 | そのセッションの末尾へ移る（`move-window`） |
| ウィンドウ | ウィンドウ行の上半分／下半分 | その手前／後ろへ差し込む。セッションをまたいでもよい |
| セッション | 別のセッション行 | 中身を全部移してひとつにまとめる（確認あり） |

落とせる場所は、セッション行なら枠が光り、ウィンドウ行なら差し込み位置に線が出る。
意味のない組み合わせ（自分自身へ、ウィンドウをウィンドウの無い所へ）は反応しない。

セッションをまとめると、移し終えて空になった側は tmux が自動的に消す。
ウィンドウの中で動いているプロセスはどちらの操作でも止まらない。

tmux の制約として、空いていない番号を指定した移動は `index in use` で失敗する。
そのため位置指定は番号ではなく「どのウィンドウの前／後ろか」で送っている。

### 一覧

| 操作 | 方法 |
| --- | --- |
| セッション作成・削除・改名 | サイドバーのボタン / 名前をダブルクリック |
| ウィンドウ作成・削除・改名・切り替え | サイドバーのツリー |
| ウィンドウの並べ替え・セッション間の移動 | サイドバーのツリーへドラッグ&ドロップ |
| セッションをひとつにまとめる | セッション行を別のセッション行へドロップ |
| 端末をタブで開く | 一覧をクリック / タブ列の ＋ / 切り替えパレット |
| タブの切り替え・並べ替え・移動 | タブをクリック / 掴んで動かす |
| ウィンドウを名前や状態で探す | `Alt+P` の切り替えパレット |
| 画面を割って複数のウィンドウを並べる | 上部バーの「右に分割 / 下に分割」、またはタブを端末の端へドラッグ |
| tmux のペインとして分割 | 端末を右クリック →「tmux のペインとして分割」 |
| ペインの選択 | 端末の中で、移りたいペインをクリック |
| ペインのズーム・削除 | 端末を右クリック |
| ペインにコマンドを送る | 上部バーの「⋯」→ コマンドを送る… |
| ペインの内容をコピー | 「⋯」→ 本文をコピー、または端末の右クリック |
| 特殊キー入力 | 画面下のキーバー（スマホでも押せる） |
| キーバインド確認 | 左端のアクティビティバーの「？」。`.tmux.conf` の実際の設定を読んで表示する |

キーボードショートカット（ブラウザ側）:

- `Alt+1`〜`Alt+9` … そのタイルの n 枚目のタブへ（`Alt+0` で右端）
- `Alt+[` / `Alt+]` … 前 / 次のタブへ
- `Alt+T` … 新しい端末をタブで開く
- `Alt+W` … いまのタブを閉じる
- `Alt+P` … ウィンドウ切り替えパレット
- `Alt+B` … サイドバーの開閉
- `Alt+/` … チートシート

これらは `keydown` の **capture 段階**で受けて止めている。bubble で受けると xterm の
ハンドラ（補助 textarea に付いている）が先に動き、`Alt+B` が `ESC b` として tmux に
流れてしまう（readline では単語単位のカーソル移動）。

確認ダイアログや入力欄はすべてアプリ内で実装している。ブラウザ標準の
`confirm()` / `prompt()` は、ページのスクリプトを丸ごと止めてしまうので使っていない。

## 接続モード：ミラー / 直接

右上のトグルで切り替える。

**ミラー（既定）** — 対象セッションと同じグループの一時セッション（`webmux-*`）を作り、
そこに attach する。ウィンドウとペインは共有されるが、**「今どのウィンドウを見ているか」が
ブラウザ側で独立する**。端末で 3 番のウィンドウを開いたまま、ブラウザで 5 番を触れる。

ただしウィンドウの**大きさ**は共有される。端末とブラウザで同じウィンドウを開くと、
tmux の仕様（`window-size latest`）により後から操作したほうのサイズに合う。これは端末を
2 つ開いて同じセッションに attach したときと同じ挙動で、避けられない。同じウィンドウを
両方で見ないようにするのが楽。

一時セッションはブラウザを閉じると削除され、サーバ起動時にも残骸を掃除する。
UI のセッション一覧にも出さない。ただし tmux は一度グループを作るとセッション名に
グループ名を覚えるため、端末で `tmux ls` すると `(group ...)` が付いて見える。
動作に影響はない。

**直接** — 対象セッションにそのまま attach する。一時セッションは作られないが、
端末側のクライアントと表示ウィンドウ・画面サイズを共有する（tmux を 2 か所から
attach したときと同じ挙動）。

### グループを共有するセッションはまとめて出す

tmux のグループ（`tmux new-session -t <既存>`）はウィンドウを共有する。
端末ごとに view を作る運用——`.bashrc` が `cw-$$` を作るような形——だと、
同じウィンドウが view の数だけ一覧に並んでしまう。中身は 1 つなので、
**同じグループのセッションはいちばん古いもの（＝元のセッション）だけ**を出す。

view のほうを個別に見たいときは `TMUX_WEB_SHOW_GROUP_VIEWS=1` で従来どおりになる。

## 設定（環境変数）

| 変数 | 既定値 | 説明 |
| --- | --- | --- |
| `PORT` | `7654` | 待ち受けポート |
| `HOST` | `127.0.0.1` | 待ち受けアドレス |
| `TMUX_WEB_TOKEN` | なし | 設定するとトークン必須になる。`http://host:7654/?token=...` で開く |
| `TMUX_WEB_SOCKET_NAME` | なし | `tmux -L <name>` 相当。別の tmux サーバを操作したいとき |
| `TMUX_WEB_SOCKET_PATH` | なし | `tmux -S <path>` 相当 |
| `TMUX_WEB_TMUX_BIN` | `tmux` | tmux の実行ファイル |
| `TMUX_WEB_SHOW_GROUP_VIEWS` | なし | `1` にすると、グループを共有するセッションをまとめずに全部出す |

## 自動起動（systemd --user）

ログイン時・再起動時に自動で立ち上げたい場合:

```bash
./scripts/install-service.sh
```

やること: `npm ci` で依存関係を同期 → フロントエンドをビルド
→ `~/.config/systemd/user/tmux-web.service` を生成
→ linger を有効化 → サービスを有効化・再起動。
linger によってログアウト後も動き、PC 起動時にはログイン前から起動する。
tmux 自体の自動起動・保存・復元は `install-persistence.sh` が導入する。
ポートやトークンは環境変数で渡すとユニットに焼き込まれる:

```bash
PORT=8080 TMUX_WEB_TOKEN=$(openssl rand -hex 24) ./scripts/install-service.sh
```

| したいこと | コマンド |
| --- | --- |
| 状態を見る | `systemctl --user status tmux-web` |
| ログを追う | `journalctl --user -u tmux-web -f` |
| 止める | `systemctl --user stop tmux-web` |
| 自動起動をやめる | `systemctl --user disable tmux-web` |
| 消す | `./scripts/uninstall-service.sh` |

コードを更新したら `./scripts/install-service.sh` をもう一度実行すれば、
依存関係を同期して再ビルドし、サービスを再起動する。
既存のポート・待ち受けアドレス・トークンは、環境変数を明示しなければ引き継ぐ。
Node.js を更新して古い実行ファイルを削除した場合も、再実行してパスを更新する。
保存・復元側も更新するなら `./scripts/setup.sh` を再実行する。

導入後の確認:

```bash
systemctl --user is-enabled tmux-web tmux-web-tmux tmux-web-resurrect-save.timer
systemctl --user is-active tmux-web tmux-web-tmux tmux-web-resurrect-save.timer
loginctl show-user "$USER" -p Linger     # Linger=yes
curl -fsS http://127.0.0.1:7654/api/state # トークン認証時はヘッダーを付ける
npm test -w server
```

2026-10-03 に Ubuntu 24.04.4 LTS / ARM64、Node.js 24.15.0、npm 11.12.1、
tmux 3.4 で導入・ビルド・API・保存を確認。
tmux 3.4 が一覧の制御文字を `\037` として返す形式にも対応する。
ARM64 の PTY / WebSocket 接続、接続 client がない状態での保存、
隔離した tmux サーバでのペイン構成・作業ディレクトリの復元、
サービス再起動時の tmux サーバ維持も確認済み。
実機の再起動は実施していない。

## 再起動をまたいでセッションを残す

tmux はサーバプロセスが死ぬとセッションを失う。何も仕込んでいなければ
ディスクに記録が残らず、再起動後に復元する手段はない。

tmux-resurrect と tmux-continuum を使う（TPM は使わず `~/.tmux/plugins/` に直接 clone）。
15 分ごとに自動保存し、tmux サーバの起動時に自動復元する。
systemd があれば PC 起動時に tmux サーバも起動し、サービス停止時にも保存する。
保存先は `~/.local/share/tmux/resurrect/`。

復元するのはセッション・ウィンドウ・ペイン構成、作業ディレクトリ、画面内容など。
実行中のプロセスのメモリ状態や、エージェントの会話をそのまま再開する機能ではない。

クローンした端末で有効にするには:

```bash
./scripts/install-persistence.sh
```

何度実行しても設定の取り込み行は重複しない。

1. tmux-resurrect / tmux-continuum を `~/.tmux/plugins/` に clone（既にあれば更新）
2. `tmux/persistence.conf` のクローン先パスと保存間隔を埋めて
   `~/.config/tmux-web/persistence.conf` に展開
3. `~/.tmux.conf` に `source-file ~/.config/tmux-web/persistence.conf` を 1 行追記
4. systemd --user があれば `tmux-web-resurrect-save.timer` を登録（15 分ごとに保存）
5. 動作中の tmux があれば設定を読み直す
6. systemd --user があれば `tmux-web-tmux.service` を登録・起動する。
   未起動のときだけ tmux を起動し、停止時に保存する。サービスを止めても tmux の作業は終了しない。

既に自分で resurrect / continuum を書いている `~/.tmux.conf` には追記しない
（`run-shell` が二重になると保存フックがぶつかるため）。その場合は手書きの行を消して
`source-file` に置き換えればリポジトリ側に寄せられる。

設定の中身は `tmux/persistence.conf`:

```tmux
set -g @resurrect-dir '~/.local/share/tmux/resurrect'
set -g @resurrect-capture-pane-contents 'on'
set -g @continuum-save-interval '@@SAVE_INTERVAL@@'
set -g @continuum-restore 'on'
set -g @resurrect-hook-post-save-all 'claude-sessions --save >/dev/null 2>&1; @@REPO_DIR@@/scripts/resurrect-strip-mirrors.sh >/dev/null 2>&1; @@REPO_DIR@@/scripts/resurrect-strip-idle.sh >/dev/null 2>&1 || true'
```

手で操作したいときは:

```bash
./scripts/resurrect-autosave.sh                         # 今すぐ保存（電源を切る前など）
tmux run-shell ~/.tmux/plugins/tmux-resurrect/scripts/restore.sh # 手動で復元（tmux 外からも可）
systemctl --user list-timers tmux-web-resurrect-save.timer   # 次の保存はいつか
systemctl --user status tmux-web-tmux.service              # tmux 自動起動（active (exited) が正常）
```

Web アプリの削除スクリプトは保存・復元サービスを残す。
それらの自動起動も止める場合は、次を実行する（tmux の構成・保存ファイルは残る）:

```bash
systemctl --user disable --now tmux-web-resurrect-save.timer tmux-web-tmux.service
```

#### 自動保存を status バーに依存させない

continuum の自動保存は `status-right` に `#(continuum_save.sh)` を差し込んで、status バーが
再描画されるたびに「前回から 15 分経ったか」を見る仕組みになっている。つまり
**status バーが描かれない限り一度も保存されない**。

tmux-web はブラウザ用のミラーセッションを `status off` で作る（ブラウザ側が独自の
ツールバーを描くため）。端末から attach せずブラウザだけで使っていると、
attach 中のクライアントは全部 status off のミラーになり、自動保存が丸ごと止まる。
実際、ブラウザからだけ使っていた 30 分のあいだ、自動保存が 1 度も走っていなかった。

そのため systemd がある環境では continuum の自動保存を切り（`@continuum-save-interval` を
`0`）、`scripts/resurrect-autosave.sh` を `tmux-web-resurrect-save.timer` から 15 分ごとに
回す。tmux サーバが動いていなければ何もせず終わる。
接続中の client がなくても `list-sessions` でサーバの稼働を判定するため、
ブラウザを閉じた状態でも保存される（`tmux info` は client 不在で失敗するため使わない）。
サーバ起動時の自動復元（`@continuum-restore`）は status バーと無関係なので、そのまま
continuum に任せる。

systemd が使えない環境では従来どおり continuum の 15 分間隔にフォールバックする。
その場合はブラウザだけで使わず、端末から 1 つ attach しておく必要がある。

戻るのはウィンドウ構成・ペイン分割・作業ディレクトリ・画面内容まで。
**実行中のプロセスは戻らない**。claude は意図的に復元対象から外してある
（起動時に大量の claude が立ち上がると困るため）。会話を続きから開くには
`claude-sessions --last --tmux` を使う。

`claude-sessions` はこのリポジトリではなく
[agent-config](https://github.com/Raptor-zip/agent-config) の `bin/` にある
（Claude Code の会話を扱うコマンドで、tmux-web が無くても単体で使うため）。
無くてもフックは黙って先へ進むので、tmux-web 側の動作には影響しない。
`install-persistence.sh` も、見つからなければその旨を出すだけで先へ進む。

### 画面の分割も一緒に戻す

ブラウザ側のタイル配置（どこを何分割して、どのウィンドウを映していたか）は
localStorage に持っている。ただし tmux を再起動すると `$1` や `@3` といった id は
resurrect が復元しても全部振り直されるので、id だけでは繋がらない。

そこでタイルにはセッション名・ウィンドウ名・ウィンドウ番号も一緒に焼き込んでおき、
サーバの pid（`#{pid}`、状態に `serverPid` として乗る）が変わったのを見て、
そのときだけ名前で繋ぎ直す。分割の形と比率はそのまま残る。

- セッションが復元されなかったタイルは閉じる
- セッションはあるがウィンドウが見つからないタイルは残し、
  そのセッションのアクティブウィンドウを映す（分割の形は崩さない）
- 同じサーバのまま閉じたウィンドウは、今まで通りタイルも閉じる
- 繋ぎ直した結果、同じウィンドウを映すタイルが 2 枚になったら 1 枚に畳む

繋ぎ直しが空振りしないよう、次の 5 つを守る。

**窓は名前より番号を信じる。**
再起動すると、中で動いていたプロセスが戻らない窓は名前が変わる。claude を動かして
いた窓は `claude` から `bash` や `node` になる。一方で番号は resurrect が保つ。
50 枚の窓のうち 47 枚が `bash` という状況では名前はほとんど手掛かりにならないので、
「名前と番号が両方合う窓 → 番号が合う窓 → 名前が合う窓」の順で探す。
名前を先に見ていたときは、別の窓を掴んだタブが正しい窓を奪い、奪われたタブが
行き先を失って（`windowId` が null になって）タイルごと消えていた。

**行き先を失ったタブは畳まない。**
`windowId` が null のタブは、そのセッションのアクティブウィンドウを映す。見た目は
同じでも、これは繋ぎ直しに失敗したタブが一時的に取る形でもあるので、重複として
畳まない。畳むと、行き先を見失っただけのタブがタイルごと消え、再起動のたびに
配置が痩せていく。

**id は当てにしない。**
tmux の id は 0 番から振り直されるので、入れ替わったあとの `$0` は前の `$0` とは
別のセッションになる。id の一致を先に見ると、覚えていた配置が丸ごと別のセッションに
繋がってしまう。セッションもウィンドウも名前（同名が複数あるときは番号）で探し、
id を頼るのは名前を焼き込む前に保存された古い配置だけにする。
繋ぎ直しが済むまでは端末も attach しない。古い id のまま繋ぐと、別のセッションの
画面が一瞬映る。

**tmux が動いていないあいだは配置に触らない。**
tmux は最後のセッションが消えるとサーバごと終わるので、状態の「セッション 0 件」は
「本当に全部消えた」ではなく「まだ繋がっていない」を意味する。ここを掃除の合図に
すると、起動直後の待ち時間（tmux-web は systemd でログインと同時に上がるが、tmux
サーバはユーザーが端末を開くまで起きない）に配置を空で上書きしてしまい、復元される
はずだったものが失われる。セッションを自分で消したときのタイルの後始末は、掃除では
なく操作した側で行う。

**復元が落ち着くまで待つ。**
resurrect はサーバが起きてから数秒かけてセッションとウィンドウを作っていく。最初の
スナップショットで判断すると、まだ戻ってきていないタブを「もう無い」と落とす。
セッションとウィンドウの顔ぶれが 2.5 秒変わらなくなってから繋ぎ直す。

**グループを畳んで残すセッションを固定する。**
グループを共有するセッションは 1 つだけ見せている。残すのを作成時刻で選ぶと、復元の
順番しだいで見えている名前が入れ替わり、名前で繋ぎ直せなくなる。グループ名と同じ
名前のもの（＝元のセッション）を優先し、無ければ古いほうを残す。

### ミラーセッションを保存から落とす

`scripts/resurrect-strip-mirrors.sh` を post-save フックから呼んでいる。

tmux-web は attach するとき対象と同じグループにミラーセッション（`webmux-*`）を作る。
グループを共有するセッションは resurrect には「原本 1 つ + `grouped_session` 参照」として
保存されるが、どちらが原本になるかは決まっていない。ミラーが原本側になったとき
`webmux-` の行を単に消すと、実セッションが参照先を失って復元できなくなる。
このスクリプトはミラーが原本なら名前を実セッション名に書き換えてから参照行を落とす。

### 未使用のウィンドウを保存から落とす

`scripts/resurrect-strip-idle.sh` を、ミラーを落としたあとに post-save フックから呼んでいる。

resurrect はウィンドウを全部保存して全部戻すが、claude などのエージェントは復元の対象外
（勝手に起こさない）。そのままだと、再起動のたびに昔のウィンドウが素の bash で戻ってきて
溜まっていく。このスクリプトは、全ペインがシェルだけ（保存ファイルの子プロセス欄が空）の
ウィンドウを保存から外す。次の再起動で戻るのは、保存した時点で何かが動いていたものだけになる。
エージェントの会話そのものは `claude-sessions --last --tmux` で戻せる。

セッションのウィンドウが全部未使用のときは、アクティブな 1 枚だけ残す。セッションごと
消すと、それを原本にしているグループのセッションが復元できなくなるため。

## Tailscale 経由でスマホから使う

`tailscale serve` に TLS を終端させ、tailnet 内の端末にだけ見せる。
アプリの bind は `127.0.0.1` のままなので、LAN にもインターネットにも出ない。

```bash
# トークン付きでサービスを入れ直してから
TMUX_WEB_TOKEN=$(openssl rand -hex 24) ./scripts/install-service.sh
./scripts/tailscale-serve.sh
```

`https://<マシン名>.<tailnet>.ts.net:8443/?token=...` が表示されるので、
スマホでこれを開いてホーム画面に追加しておく（トークンは URL のクエリで渡す方式なので、
ブックマークしておけば毎回貼り直さずに済む）。

| したいこと | コマンド |
| --- | --- |
| URL を再表示 | `./scripts/tailscale-serve.sh url` |
| 公開をやめる | `./scripts/tailscale-serve.sh off` |
| 公開状況を見る | `tailscale serve status` |
| ポートを変える | `TS_PORT=10000 ./scripts/tailscale-serve.sh` |

HTTPS で配信されるのは体裁の問題だけではない。ブラウザはクリップボード API などを
secure context でしか許さず、`http://100.x.y.z` は secure context 扱いにならないため、
生の Tailscale IP に直接 bind するより `tailscale serve` のほうが素直に動く。

`tailscale funnel` を使えばインターネットにも出せるが、このアプリの性質上やめたほうがいい。

## セキュリティ

**このアプリはシェルへの完全なアクセスを HTTP 越しに提供する。**
既定で `127.0.0.1` にしか bind しないのはそのため。

LAN や外部に出す場合は最低限これを守ること:

```bash
TMUX_WEB_TOKEN=$(openssl rand -hex 24) HOST=0.0.0.0 npm start
```

より安全なのは、bind は `127.0.0.1` のままにして SSH ポート転送で繋ぐ方法:

```bash
ssh -N -L 7654:127.0.0.1:7654 user@remote-host
```

## 構成

```
server/src/
  index.js    Express + WebSocket。REST（状態取得・操作）と端末ストリーム
  tmux.js     tmux CLI のラッパ。shell を介さず execFile で呼ぶ
  attach.js   node-pty でミラーセッションに attach し、後片付けまで面倒を見る
web/src/
  App.tsx              画面全体の状態
  api.ts               REST クライアント + 状態 push の購読
  layout.ts            タブと画面分割の二分木、そこから矩形を求める純粋な計算
  windows.ts           ウィンドウ 1 つの見せ方（一覧・タブ・パレットで共通）
  paths.ts             パスとプロジェクト名の見せ方（一覧と見出しで揃える）
  status.ts            プロセス判定を 5 つの状態にまとめる
  components/
    SplitView.tsx      タイルの配置・ドラッグ&ドロップ・境界線のリサイズ
    TabStrip.tsx       タイルごとのタブ列
    Terminal.tsx       xterm.js。WebSocket と繋ぐ
    Sidebar.tsx        セッション／ウィンドウのツリー
    Switcher.tsx       ウィンドウ切り替えパレット (Alt+P)
    Toolbar.tsx        パンくずと分割・コマンド送信
    KeyBar.tsx         特殊キーのツールバー
    CheatSheet.tsx     キーバインド一覧
    Dialog.tsx         確認・入力ダイアログ
tmux/
  persistence.conf     resurrect / continuum の設定断片（インストーラが展開する）
scripts/
  install-service.sh          systemd --user への登録
  install-persistence.sh      セッション保存・復元の仕組みを入れる
  resurrect-autosave.sh       systemd タイマーから叩く保存（status バーに依存しない）
  resurrect-strip-mirrors.sh  保存ファイルからミラーセッションを落とす
  resurrect-strip-idle.sh     保存ファイルから未使用（シェルだけ）のウィンドウを落とす
  tailscale-serve.sh          tailnet に公開する
```

分割レイアウトは二分木で持ち、葉（タイル）が**タブの束**を持つ。描画は木構造のままではなく
**各タイルの矩形（%）を計算してフラットに絶対配置する**。木のままネストして描くと
分割のたびにタイルの DOM 上の位置が変わり、React が Terminal を作り直して
tmux に繋ぎ直してしまうため。端末はタイルに 1 つで、タブを切り替えるときは
同じ接続のまま tmux 側の表示ウィンドウを差し替える（セッションをまたぐときだけ張り直す）。

`localStorage` に古い形（1 タイル = 1 ウィンドウ）が残っていても、読み込み時に
タブの形へ読み替える。保存キーを変えて捨てると、開いていた配置が一度だけ消えるため。

状態は tmux の `list-sessions` / `list-windows -a` / `list-panes -a` を
1.2 秒ごとに読み、変化があったときだけ WebSocket で push する。
操作系はすべて `tmux` のサブコマンドを呼ぶだけなので、tmux 側の状態が正になる。

### スマホでの入力

- iPhone でホーム画面に追加して起動した場合も、上部ボタン・サイドバー・下部の操作を
  `safe-area-inset-*` の内側に配置する。Dynamic Island、横向きの切り欠き、ホームバーとの重なりを避ける。
  余白は [WebKit の safe area の説明](https://webkit.org/blog/7929/designing-websites-for-iphone-x/) に沿って設定する。
  更新後はホーム画面のアプリをアプリ切り替え画面から終了し、開き直す。
- 端末の上を上下にスワイプすると、tmux の履歴や端末内のアプリをスクロールできます。
- 下部の入力欄で日本語を入力・変換し、「端末に挿入」で確定した文章を端末へ渡します。「Enter」は別操作なので、挿入後に内容を確認できます。
- 「貼り付け」は入力欄へ取り込みます。ブラウザがクリップボードへのアクセスを許可しない場合（HTTP 接続など）は、入力欄を長押しして貼り付けてください。
- 入力欄の改行は下書きの改行です。端末への挿入には xterm の貼り付け処理を使い、アプリが bracketed paste を有効にしている場合はその方式で送ります。

### ファイル一覧とプレビュー

端末上部の「ファイル」から、その端末のプロジェクトフォルダを開けます。プロジェクトが判別できない場合はペインの作業フォルダを使います。

- 「アップロード」またはファイルのドロップで、表示中のフォルダへ複数ファイルを送れます（1件50MBまで）。同名ファイルは連番で保存します。
- 「フォルダーを保存」で、現在のフォルダを tar.gz にまとめてダウンロードできます。隠しファイル・node_modules は含めません。
- フォルダを移動し、ファイル名で絞り込み、更新順・名前順を切り替えられます。「更新」で現在のフォルダを読み直します。
- 画像・PDF・動画・音声・テキストをプレビューし、ダウンロードできます。動画・音声はブラウザが対応する形式で再生できます。
- スマホではファイルを選ぶとプレビューへ切り替わり、「← 一覧」で戻れます。PDF は別タブでも開けます。
- 隠しファイル、`node_modules`、`__pycache__`、作業フォルダ外へのリンクは表示・配信しません。HTML 等はダウンロード扱いです。
- 一覧と閲覧リンクの発行には既存の `TMUX_WEB_TOKEN` 認証を使います。メディア用のリンクはファイル単位の署名付きで、有効期間は 1 時間です。期限切れやサーバ再起動後は一覧から開き直してください。

ファイル API のテスト: `npm test -w server`
